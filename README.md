# ВКР: реализация модели извлечения структурированных атрибутов товаров из их текстовых описаний

Автор: Тимофеев К Ю, ПМ23-5. Дисциплина: «Прикладные задачи машинного обучения», ЛР-1.

## Идея

Из русскоязычного описания товара нужно получить JSON «атрибут → значение» по схеме категории (сейчас категория «Мониторы», 7 атрибутов: диагональ, разрешение, частота, тип матрицы, яркость, контрастность, изогнутость).

Сравниваются 8 открытых LLM размером до 9B (GigaChat — MoE на 10B с 1,8B активных) в 4-битной точности на одной A100 по единому протоколу: zero-shot, few-shot, а на лучшей и самой слабой модели LoRA и QLoRA на синтетике. Малые модели выбраны, чтобы был виден эффект приёмов, а не потолок сильной модели.

Данные:
- **Синтетика.** Описания пишет Claude по заданным атрибутам, разметка известна по построению. Идёт на примеры few-shot и на обучение LoRA.
- **Реальные карточки DNS** (скрапинг). Делятся на **real-val** (выбор модели, промпта, learning rate) и **real-test** (один финальный прогон).
- Эталон реальных карточек: значение из таблицы характеристик DNS, если оно названо в тексте описания, иначе `null`.

Claude только генерирует синтетику и в сравнении моделей не участвует.

## Структура

```
01_literature/   обзор литературы: ноутбук, матрица источников, PRISMA-схема, список источников
02_scraping/     сбор карточек DNS: юзерскрипт, скрипт прокрутки, промпт, README
03_eda/          предварительный анализ данных: ноутбук, эталон, разбиение pilot / real-val / real-test
04_synthetic/    генерация синтетики через Claude: скрипт, проверка, README
05_protocol/     протокол: 8 моделей, ноутбук прогона одной модели, скрипт bootstrap.py
06_pilot/        пилот на 100 карточках: результаты, пороги (thresholds.md)
07_main_run/     основной прогон на real-val и heldout: ноутбук, результаты, разбор ошибок
data/            данные (не коммитится)
```

Отчёты (`*.docx`) лежат рядом с этапами и в `.gitignore`. Полный текст отчёта собирается в `текст.docx`.

## Этапы

- [x] 01. Обзор литературы: 14 источников, матрица, гипотезы H1–H9 в двух группах (без дообучения и LoRA/QLoRA), решения для эксперимента
- [x] 02. Скрапинг DNS: юзерскрипт v0.5 (случайный выбор, только товары в наличии)
- [x] 03. Анализ данных на 494 карточках (500 собрано, 6 смарт-мониторов убрано): эталон по тексту, форматы записи, проверка карточек, дубликаты, разбиение пилот 100 / real-val 158 / real-test 236
- [x] 04. Синтетика: готовы fewshot (20), heldout (80) и train (1000); генерация Claude, автопроверка (значения из эталона есть в тексте, для `null` нет), сверка длин и форматов записи с реальными
- [x] 05. Протокол: 8 моделей, метрики, схема JSON, промпты zero-shot / few-shot, ноутбук `05_protocol/05_run_model.ipynb` (одна модель, все четыре режима), скрипт `bootstrap.py`
- [x] 06. Пилот на 100 карточках: 8 моделей × 4 режима, результаты в `06_pilot/results/`, пороги и допуски в `06_pilot/thresholds.md`
- [ ] 07. Основной прогон 8 моделей на real-val, статистика (bootstrap), разбор ошибок, выбор лучшей модели (план в `07_main_run/README.md`)
- [ ] 08. LoRA и QLoRA на лучшей и самой слабой модели (предварительно, решим после пилота; сравнение качества и памяти)
- [ ] 09. Финальный прогон на real-test (один раз), итоговый отчёт

Названия папок 04–09 предварительные.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
jupyter notebook
```

Каждый ноутбук запускается из своей папки (пути вида `outputs/...` и `../data/...` считаются от неё). Данные кладутся в `data/`: `03_eda/03_eda.ipynb` читает `data/dns_cards_500.json` (переменная `DATA`), убирает смарт-мониторы и пишет `data/<имя>_gold.json` и `03_eda/outputs/<имя>/`. Для анализа пилота поставь `HEAD = 100`.

## Правила эксперимента

- Решения (модель, промпт, learning rate) принимаются только по real-val.
- real-test открывается один раз.
- Пороги гипотез фиксируются до основных прогонов.
- Скрапленные тексты в репозиторий не добавляются (только идентификаторы и ссылки).
- Оптимизатор для LoRA один (AdamW), сравнения оптимизаторов нет.
