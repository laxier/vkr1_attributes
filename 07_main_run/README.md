
# 07. Основной прогон

Вводная часть фиксирует протокол до анализа результатов. Пороговые значения и правила выбора не меняются после просмотра результатов. Итоговые выводы по гипотезам дополняются после bootstrap-анализа, проверки `heldout` и разбора ошибок.

## Цель

Сравнить 8 моделей на `real_val` (158 карточек), проверить H2–H5, разобрать ошибки и выбрать кандидата по заранее заданному правилу. H1 считается предварительной до финальной проверки на `real_test` в этапе 09.

## Что проверяем

| Гипотеза                                                                                       | Данные                           | Критерий                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1 (предварительная)                                                                    | `real_val`, затем `real_test` | невалидных < 1%, micro-F1 ≥ T1, ложные на `null` ≤ T2; окончательный вывод — только после `real_test` |
| H2: few-shot помогает                                                                          | `real_val`                           | few-shot − zero-shot ≥ +0,02; 95%-й парный bootstrap-интервал разницы не содержит 0                                       |
| H3: схема уменьшает невалидные почти без потери качества | `real_val`                           | невалидных со схемой < 1%, потеря F1 ≤ 0,02                                                                                        |

H6–H9 (LoRA и QLoRA) относятся к этапу 08 и позже. Значения T1 и T2 берутся из `06_pilot/thresholds.md`; их нужно дословно перенести в итоговый отчёт, если они не указаны в нём явно.

Инструкция, пять few-shot-примеров и эталон должны совпадать с пилотом. `real_test` не открываем. Дополнительный прогон с перефразированной инструкцией — необязательный и не должен влиять на выбор модели по основному протоколу.

## Метрики и статистика

Главная метрика — micro-F1 с нормализацией. Дополнительно сохраняются: строгий micro-F1, macro-F1, exact match, ложные срабатывания на `null`, доля невалидных ответов, среднее и p95 времени на карточку, токены, пиковая память и версии окружения.

- Парный bootstrap по карточкам: 4000 повторов, `seed=0`, 95%-й интервал.
- Разница считается статистически различимой от нуля, если интервал не содержит 0.
- Дополнительная метрика без пар с названием разрешения (например, Full HD, QHD, 4K без цифр) не заменяет основную и не используется для отбора.
- Группы почти-дубликатов для `real_val` пока не заданы. Поэтому интервалы по карточкам могут быть уже, чем интервалы с учётом зависимости между похожими карточками; это ограничение нужно указать в отчёте.

## Правило выбора лучшей модели

1. Для каждой модели выбрать лучший из четырёх запусков по нормализованному micro-F1.
2. Применить фильтры: невалидных < 1%, F1 ≥ T1, ложные на `null` ≤ T2.
3. Среди прошедших выбрать модель с минимальным числом ложных на `null`. Различия считать неразличимыми, если 95%-й интервал парной bootstrap-разницы содержит 0. Среди неразличимых выбрать более быструю по среднему времени на карточку в лучшем запуске.
4. Стоимость оценивать как `сек/карточку × 1000 / 3600 × 5,4` единицы Colab на 1000 карточек. При одинаковой конфигурации порядок стоимости совпадает с порядком времени.
5. Если никто не прошёл, пороги не менять: сообщить, что кандидатов нет, и назвать ближайшую модель. Если T2 проходят меньше двух моделей, отдельно отметить, что надёжное сравнение нескольких прошедших моделей по этому правилу невозможно.

- **H5:** агрегированного `summary.csv` недостаточно, чтобы вычислить доли типов ошибок и долю ошибок формата. Нужны предсказания по карточкам, эталон и результаты строгого сравнения до/после нормализации. Нельзя объявлять H5 подтверждённой только по разнице строгого и нормализованного F1.

## Разбор ошибок

Типы: ошибка формата (исправляется нормализацией), неверное значение, пропуск, лишнее значение; отдельная подкатегория лишнего значения — название разрешения без цифр.

Доля ошибок формата = число пар, исправленных нормализацией / число всех ошибок при строгом сравнении. Для лучшей модели вручную разобрать не менее 10 случаев каждого типа, если столько случаев есть. Эталон на этом этапе не менять; спорные случаи записать отдельно.
