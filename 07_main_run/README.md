# 07. Основной прогон

Вводная часть этапа: что запускаем, что считаем и по каким правилам делаем выводы, до того как появятся результаты. Результаты и разбор ошибок дописываются после прогона.

## Цель

Сравнить 8 моделей на `real_val` (158 карточек) по протоколу этапа 05, проверить гипотезы H2–H5, разобрать ошибки и выбрать лучшую модель по правилу, записанному заранее. Пороги и допуски берём из `06_pilot/thresholds.md`, они не меняются.

## Что проверяем

| № | утверждение | данные | правило |
|---|---|---|---|
| H1 (предв.) | лучшая модель проходит порог F1 при невалидных < 1% | real_val | невалидных < 1%, micro-F1 ≥ 0,90 (T1), ложные на `null` ≤ 0,10 (T2); окончательно на `real_test` (этап 09) |
| H2 | примеры в промпте дают прирост | real_val | few-shot − zero-shot ≥ +0,02 и интервал bootstrap без 0 |
| H3 | схема снижает невалидные до < 1% почти без потери F1 | real_val | невалидных со схемой < 1%, потеря F1 ≤ 0,02 |
| H4 | падение F1 при переходе от синтетики к реальным небольшое | heldout, real_val | F1(heldout) − F1(real_val) ≤ 0,05 |
| H5 | ошибки формата — самая большая доля; нормализация даёт прирост | real_val | доли типов ошибок; F1 норм − F1 строго ≥ +0,02 |

H6–H9 (LoRA и QLoRA) относятся к этапу 08 и позже.

## Что запускаем

| набор | карточек | запусков | что | зачем |
|---|---|---|---|---|
| `real_val` | 158 | 32 | 8 моделей × 4 запуска (zero-shot / few-shot, свободно / схема) | H2, H3, H5, отбор |
| `heldout` | 80 | 8 | лучший запуск каждой модели по `real_val` | H4 |
| `real_val` (доп.) | 158 | 3 | 3 лучшие модели, перефразированная инструкция | чувствительность к формулировке (предложение, решает автор) |

Инструкция, 5 примеров few-shot и эталон те же, что на пилоте. `real_test` не открываем.

## Метрики и статистика

- Главная метрика: micro-F1 с нормализацией. Рядом: ложные на `null`, невалидные, строгий F1, macro-F1, exact match, время на карточку, входные и выходные токены, пиковая память.
- Интервалы: парный bootstrap по карточкам, 4000 повторов, seed 0, 95%. Разница значима, если интервал не содержит 0.
- Вторая метрика «без пар с названием разрешения» (Full HD, QHD, 4K без цифр): решения по порогам принимаются по основной.
- Файла групп почти-дубликатов для `real_val` пока нет, интервалы будут по карточкам.

## Выбор лучшей модели

1. У каждой модели берём лучший запуск по micro-F1.
2. Фильтр: невалидных < 1%, F1 ≥ T1, ложные на `null` ≤ T2.
3. Среди прошедших: минимум ложных на `null`. Равны, если интервал парной разности (bootstrap) содержит 0; из равных — более быстрая (сек/карточка лучшего запуска). Стоимость = сек × 1000 / 3600 × 5,4 единицы Colab на 1000 карточек, порядок тот же, что по времени.
4. Никто не прошёл — это результат: пороги не двигаем, называем ближайшую модель. Прошли меньше двух по T2 — тоже результат.

## Разбор ошибок

Типы: формат значения (нормализация исправляет), неверное значение, пропуск, лишнее значение (из них: название разрешения без цифр). Доля ошибок формата = пары, исправленные нормализацией / все ошибки при строгом сравнении. Для лучшей модели смотрим вручную не меньше 10 случаев каждого типа. Эталон на этом этапе не правим.
